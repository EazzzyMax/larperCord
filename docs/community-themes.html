Open the theme builder How to send a theme

pull request { // how to send yours

Send yours. One file, one pull request.

  1. Make the theme in the theme builder, or by hand with Writing themes. In the builder's File info tab, fill in the name, the author, a description and the license: the panel under the preview lists anything still missing.
  2. Download the .kdl. Its name comes from the theme's name: "Neon Dusk" becomes neon-dusk.kdl.
  3. Fork the repository, add the file to themes/community/ and open a pull request. One theme per pull request.
  4. Optional, before sending: python3 tools/gen_site.py --check-community runs the same checks as CI, and larpercord --theme neon-dusk (with the file in your themes folder) shows it in the app.
  • It has to load in the app. The site build reads every file in the folder with the app's rules (syntax, color tokens, color expressions, component names) and stops with file:line:column at the first problem. The tests then load each theme with the site's copy of the app's theme loader, in both modes and with every option. CI runs both on every pull request. To be sure, try it in the app itself (step 4).
  • A name of its own. Not the name of a built-in theme (a file called orbital.kdl would take its place in the app) and not one already in the gallery. A built-in theme with only the name changed is turned away too.
  • No copyrighted logos or fonts. The folder only takes .kdl files, so no images or font files. Don't redraw someone else's logo with label, shape or ASCII art, and only name fonts that people can get freely: the app looks the family up on their system.
  • An open license. license= on the theme node, one from the gallery's list written as its SPDX identifier (CC0-1.0, CC-BY-4.0, MIT, GPL-3.0-or-later…), so people know they may use and change it. If the colors came from someone else's theme, its license has to allow that, and the description should credit the author.
