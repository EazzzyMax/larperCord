pull request { // {{how to send yours||como mandar o seu}}

{{Send yours. One file, one pull request.||Mande o seu. Um arquivo, um pull request.}}

  1. {{Make the theme in the theme builder, or by hand with Writing themes. In the builder's File info tab, fill in the name, the author, a description and the license: the panel under the preview lists anything still missing.||Faça o tema no criador de temas, ou à mão com Escrevendo temas. Na aba Arquivo do criador, preencha o nome, o autor, uma descrição e a licença: o painel embaixo da prévia mostra o que ainda falta.}}
  2. {{Download the .kdl. Its name comes from the theme's name: "Neon Dusk" becomes neon-dusk.kdl.||Baixe o .kdl. O nome dele vem do nome do tema: "Neon Dusk" vira neon-dusk.kdl.}}
  3. {{Fork the repository, add the file to themes/community/ and open a pull request. One theme per pull request.||Faça um fork do repositório, coloque o arquivo em themes/community/ e abra um pull request. Um tema por pull request.}}
  4. {{Optional, before sending: python3 tools/gen_site.py --check-community runs the same checks as CI, and larpercord --theme neon-dusk (with the file in your themes folder) shows it in the app.||Opcional, antes de mandar: python3 tools/gen_site.py --check-community roda as mesmas checagens do CI, e larpercord --theme neon-dusk (com o arquivo na sua pasta de temas) mostra ele no app.}}
  • {{It has to load in the app. The site build reads every file in the folder with the app's rules (syntax, color tokens, color expressions, component names) and stops with file:line:column at the first problem. The tests then load each theme with the site's copy of the app's theme loader, in both modes and with every option. CI runs both on every pull request. To be sure, try it in the app itself (step 4).||Ele tem de carregar no app. O build do site lê cada arquivo da pasta com as regras do app (sintaxe, tokens de cor, expressões de cor, nomes de componentes) e para com arquivo:linha:coluna no primeiro problema. Depois, os testes carregam cada tema com a cópia que o site tem do leitor de temas do app, nos dois modos e com todas as opções. O CI roda os dois em todo pull request. Para ter certeza, teste no próprio app (passo 4).}}
  • {{A name of its own. Not the name of a built-in theme (a file called orbital.kdl would take its place in the app) and not one already in the gallery. A built-in theme with only the name changed is turned away too.||Um nome só dele. Nem o nome de um tema embutido (um arquivo chamado orbital.kdl tomaria o lugar dele no app) nem um que já esteja na galeria. Um tema embutido só com o nome trocado também volta.}}
  • {{No copyrighted logos or fonts. The folder only takes .kdl files, so no images or font files. Don't redraw someone else's logo with label, shape or ASCII art, and only name fonts that people can get freely: the app looks the family up on their system.||Sem logos nem fontes protegidos. A pasta só aceita arquivos .kdl, então nada de imagens ou arquivos de fonte. Não redesenhe o logo de outra pessoa com label, shape ou arte em ASCII, e só cite fontes que dá para conseguir de graça: o app procura a família no sistema de quem usa.}}
  • {{An open license. license= on the theme node, one from the gallery's list written as its SPDX identifier (CC0-1.0, CC-BY-4.0, MIT, GPL-3.0-or-later…), so people know they may use and change it. If the colors came from someone else's theme, its license has to allow that, and the description should credit the author.||Uma licença aberta. license= no nó theme, uma da lista da galeria escrita como o identificador SPDX dela (CC0-1.0, CC-BY-4.0, MIT, GPL-3.0-or-later…), para todo mundo saber que pode usar e mudar. Se as cores vieram do tema de outra pessoa, a licença dele tem de deixar, e a descrição deve dar o crédito.}}
